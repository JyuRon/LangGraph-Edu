"데이터(Payload)를 안 넘기면 어떻게 될까?"라는 질문은 LangGraph의 상태(State) 관리 원리를 이해하는 데 아주 중요한 포인트입니다!

결론부터 말씀드리면, **데이터를 안 넘기거나 잘못 넘기면 파이썬 문법 에러가 나거나 해당 노드(워커)가 뻗어버립니다.**

구체적으로 어떤 일이 벌어지는지 세 가지 시나리오로 나누어 백엔드 시스템에 비유해 설명해 드릴게요.

---

### 1. 문법적 에러: 아예 안 적었을 때 (`TypeError`)

`Send` 클래스는 태생적으로 "어디로(node)"와 "무엇을(arg)"이라는 두 개의 파라미터를 필수로 받도록 설계되어 있습니다.

```python
# ❌ 에러 발생! 두 번째 인자(데이터)가 없습니다.
return [Send("generate_joke")] 

```

이 경우 파이썬 자체가 `TypeError: Send.__init__() missing 1 required positional argument: 'arg'` 에러를 뱉으며 그래프가 아예 시작조차 하지 못하고 죽어버립니다.

### 2. 빈 데이터를 넘겼을 때 (`KeyError`)

문법 에러를 피하려고 빈 딕셔너리(`{}`)를 넘긴다면 어떻게 될까요?

```python
# 껍데기만 보냄
return [Send("generate_joke", {})] 

```

이 명령서를 받은 `generate_joke` 노드는 빈 딕셔너리를 자신의 상태(`state`)로 착각하고 실행을 시작합니다.

```python
def generate_joke(state: dict):
    # 빈 딕셔너리 {} 에서 "subject"를 꺼내려 하므로 여기서 펑! 터집니다.
    subject = state["subject"] # ❌ KeyError 발생!

```

비유하자면, **택배 기사(워커)를 목적지(타겟 노드)로 출발은 시켰는데, 배달할 물건(데이터)을 안 쥐여준 것**과 같습니다. 도착해서 상자를 열어보니 텅 비어있어서 작업자가 당황하며 에러를 내는 것이죠.

### 3. 💡 핵심: 왜 꼭 '잘라서' 넘겨야 할까? (아키텍처 관점)

만약 `Send`를 쓰지 않고 일반적인 방식으로 엣지(Edge)를 연결했다면, 타겟 노드는 전체 상태(OverallState)를 통째로 넘겨받습니다.

```python
# 전체 상태
OverallState = {
    "subjects": ["정치", "경제", "스포츠"],
    "jokes": []
}

```

워커 노드가 전체 데이터를 다 받으면 **"어? 나는 농담 1개만 짜는 역할인데, 주제가 3개나 있네? 이 중에 대체 뭘로 농담을 만들라는 거지?"** 하고 혼란에 빠집니다.

그래서 라우터 역할을 하는 노드가 전체 데이터(`subjects` 리스트)를 잘게 쪼개서, **"너는 정치만 해!" (`{"subject": "정치"}`)**, **"너는 경제만 해!" (`{"subject": "경제"}`)** 라고 각 워커에게 명확한 로컬 상태(Local State)를 쥐여주는 것입니다.

### 📝 요약

`Send`의 두 번째 인자는 API 요청을 보낼 때의 Request Body(페이로드)와 같습니다.
게시글 작성 API를 호출하면서 제목과 내용을 안 넘기면 서버가 400 Bad Request 에러를 내뿜듯이, LangGraph의 타겟 노드도 작업을 수행할 필수 데이터가 없으면 즉시 에러를 발생시키며 전체 그래프를 중단시킵니다.
