### 1. `jump_to`는 약속된 명칭인가요?

**네, 맞습니다.** LangGraph(또는 LangChain) 프레임워크 내부에서 파이프라인의 실행 흐름을 동적으로 통제하기 위해 미리 정의해 둔 공식 예약어(Reserved Key)입니다.

미들웨어 함수가 로직 처리를 마친 후 `{"jump_to": "목적지"}` 형태의 데이터를 반환하면, 프레임워크는 이를 인식하고 원래 예정되어 있던 다음 단계(예: LLM 호출)를 취소한 뒤 지정된 목적지로 강제 이동(라우팅)시킵니다. Spring에서 비즈니스 로직 처리 중 `return "redirect:/error"`를 통해 흐름을 꺾어버리는 것과 완벽히 같은 원리로 동작합니다.

### 2. `can_jump_to`에는 어떤 값들이 들어갈 수 있나요?

제어 흐름을 어디로 보낼지에 따라 주로 다음 세 가지 목적지가 리스트 형태로 들어갈 수 있습니다.

* **`"end"` (조기 종료 및 차단)**
* **동작:** 에이전트 루프를 즉시 중단하고 파이프라인을 빠져나갑니다.
* **활용 포인트:** 시스템 프롬프트를 탈취하려는 인젝션 공격이 감지되었을 때 LLM 호출을 원천 차단(보안 가드레일)하거나, 무료 과금 한도를 초과했을 때, 혹은 이전 답변이 캐싱되어 있어 무거운 연산을 태울 필요가 없을 때 사용합니다.


* **`"tools"` (도구 실행으로 강제 점프)**
* **동작:** LLM의 추론 과정을 건너뛰고 곧바로 도구(Tool/Action) 실행 노드로 넘어갑니다.
* **활용 포인트:** 사용자의 특정 질문 패턴이 들어왔을 때, 굳이 LLM의 판단을 거치지 않고 미들웨어 단에서 즉시 사내 DB 검색 도구나 API 호출 도구로 흐름을 넘겨버릴 때 유용합니다.


* **`"model"` (모델 재호출 / Retry)**
* **동작:** 실행 흐름을 다시 LLM 노드로 돌려보냅니다. (이 값은 주로 모델 실행 후 작동하는 `@after_model` 훅에서 자주 쓰입니다.)
* **활용 포인트:** LLM이 반환한 답변의 JSON 포맷이 깨졌거나 보안 검열에 걸렸을 때, "포맷이 틀렸거나 민감 정보가 포함되었으니 다시 작성해라"라는 피드백과 함께 모델을 재호출할 때 사용합니다.



---

### 💡 요약: 두 가지가 반드시 세트로 쓰여야 하는 이유

LangGraph는 런타임 에러를 방지하고 보안을 강화하기 위해 앱 실행 전 전체 그래프의 노드 연결망(Edge)을 미리 렌더링하고 검증합니다.

따라서 `@before_model(can_jump_to=["end"])` 데코레이터를 통해 **"이 방어막(미들웨어)은 상황에 따라 파이프라인을 'end'로 즉시 종료시킬 수 있는 권한과 경로를 가지고 있다"고 프레임워크에 사전 신고**를 해두어야 합니다. 이 명세 과정이 있어야만 내부 로직에서 실제로 `{"jump_to": "end"}`를 반환했을 때 에러 없이 안전하게 라우팅이 동작합니다.
